# K탁구클럽 홈페이지 (GitHub Pages용 HTML 버전)

**K탁구클럽 실제 사진으로 만든 회원 홈페이지와 관리자 페이지입니다.**
파이썬/Flask를 설치하지 않고 GitHub Pages에서 열 수 있는 **HTML + CSS + JavaScript 정적 웹사이트**로 구성했습니다.

## 포함된 페이지

| 파일 | 기능 |
|---|---|
| `index.html` | 클럽 소개, 현장 사진, 체험 및 정기 레슨 시간표, 온라인 예약 신청 |
| `admin.html` | 관리자 이메일/비밀번호 로그인, 예약 목록·상태 확인, 입금 확인, 일정 변경, CSV 저장 |
| `assets/styles.css` | 모바일과 PC 반응형 디자인 |
| `assets/app.js` | 예약 화면 처리, 계좌 복사, 안내 및 필수 동의 |
| `assets/admin.js` | 관리자 예약 조회/상태 변경/예약 날짜 변경/CSV 다운로드 |
| `assets/api.js` | Supabase 인증 및 예약 API 통신 |
| `assets/config.js` | 웹사이트의 Supabase 연결 설정 |
| `assets/images/` | 사용자가 제공한 **실제 K탁구클럽 사진**을 최적화한 이미지 |
| `database.sql` | Supabase에서 실행할 테이블/예약 규칙/관리자 권한 설정 |

## 1단계: 홈페이지 파일 확인

`index.html`을 브라우저에서 열면 디자인 미리보기는 가능합니다. 아직 Supabase가 연결되지 않았으므로 **실제 신청 저장은 작동하지 않습니다.** 미리보기에서 시간 선택은 할 수 있지만 신청 시 연결 안내가 표시됩니다. 정상 운영은 2~4단계를 거쳐야 합니다.

## 2단계: Supabase 프로젝트 생성

1. https://supabase.com 에서 프로젝트 생성 후 관리 화면으로 이동합니다.
2. **SQL Editor → New query**에서 `database.sql` 내용을 전부 붙여 넣고 **Run**으로 실행합니다.
3. 프로젝트의 **Project URL**과 **Publishable key** (`sb_publishable_...`)를 확인합니다. 이전 방식의 **anon key**도 사용할 수 있습니다. **Secret key 또는 service_role key는 절대 사용하지 마세요.**
4. `assets/config.js`를 아래와 같이 수정합니다.

```javascript
window.KTT_CONFIG = {
  supabaseUrl: 'https://프로젝트ID.supabase.co',
  supabaseAnonKey: 'sb_publishable_여기에_공개용_키'
};
```

> `config.js`는 GitHub 공개 저장소에 올라갑니다. **Supabase Publishable Key는 공개 클라이언트용 키**이며, 실제 개인정보 보호는 `database.sql`에서 지정한 RLS + RPC 권한으로 수행합니다. **관리자 비밀번호와 Secret key를 config.js에 넣지 마세요.**

## 3단계: 관리자 계정 등록

1. Supabase → **Authentication → Users** 에서 `Add user`로 관리자 이메일/비밀번호 계정을 만듭니다. 가입 방식/화면 이름은 프로젝트 설정에 따라 조금 다를 수 있습니다.
2. Supabase → **SQL Editor**에서 아래 SQL을 실행합니다. 이메일은 **직접 만든 관리자 이메일**로 수정합니다.

```sql
insert into public.ktt_admin_users (user_id)
select id from auth.users where email = '관리자이메일@example.com'
on conflict (user_id) do nothing;
```

3. `admin.html`에서 해당 이메일/비밀번호로 로그인합니다.
4. `ktt_admin_users`에 등록되지 않은 일반 계정으로는 관리자 RPC(예약자 이름/전화번호 조회 및 변경)를 실행할 수 없습니다.

## 4단계: GitHub Pages 게시

1. https://github.com 에서 새 Repository 생성(예: `k-table-tennis-club`).
2. 압축 파일을 풀고 **압축 해제된 폴더 안의 파일과 `assets` 폴더 전체**를 Repository 최상위에 업로드합니다. `index.html`이 저장소 최상위에 있어야 합니다.
3. `Settings → Pages → Build and deployment`의 Source를 `Deploy from a branch`로 설정합니다.
4. Branch를 `main`, Folder를 `/(root)`로 선택한 뒤 Save합니다.
5. 사이트가 배포되면 `https://깃허브아이디.github.io/저장소이름/` 주소로 회원용 홈페이지가, **`.../admin.html`** 주소로 관리자 페이지가 열립니다.

> GitHub Pages는 HTML/CSS/JS를 공개해 줄 뿐 **예약 데이터를 저장할 서버나 관리자 로그인 서버가 아닙니다.** 이 프로젝트는 Supabase를 백엔드로 연동하도록 만들었습니다. GitHub에 올리는 것만으로는 실제 예약 및 입금확인이 작동하지 않습니다.

## 동작 방식

### 회원 예약
- 날짜/30분 시간 선택 → 이름/연락처/실력/레슨 경험 → 개인정보 및 환불 규정 동의 → 신청
- **체험**은 `입금 확인 대기`, **정기 레슨**은 `예약 확인 대기` 상태로 저장
- 동일 날짜/시간 중복 예약 차단(데이터베이스 고유 인덱스)
- 무료 체험 1회 제한은 연락처 기준으로 서버에서 검사
- 체험 결제 계좌, 장소사용료 안내는 예약 화면과 완료 메시지에 표시

### 관리자 운영
- 실제 카카오뱅크 입금 내역을 확인한 뒤 관리자 페이지에서 **예약 확정**으로 변경
- 확정/완료/노쇼/취소 상태 변경 및 **입금 확인·예약 확정 안내문 복사**(관리자가 문자로 직접 발송)
- 날짜·유형·상태별 필터 및 CSV 다운로드
- 예약 시작 **24시간 이전**에만 일정 변경 가능(서버도 규칙 검증)
- 관리자는 실제 환불/연락을 별도로 처리해야 함

## 실제 운영 전 필수 확인 사항

1. **은행 계좌 자동 입금확인 없음**: 안내 문구 및 수동 상태 변경만 지원합니다. 입금 확인 문자나 알림톡, 예약 확정 문자는 자동 발송되지 않습니다.
2. **개인정보 처리방침 확인**: 현재 개인정보 동의 내용에 보유기간은 확정되지 않았다고 명시되어 있습니다. 공개 운영 전 보유기간, 삭제 주기, 사업자 정보 및 운영자 개인정보 처리방침을 확정·반영해 주세요.
3. **보안/스팸 관리**: 누구나 공개 예약을 신청하는 방식이므로 대량 자동 신청 및 악의적인 예약 방지를 위해 운영 시 레이트 리밋/CAPTCHA 또는 별도 서버 측 검증을 추가하는 것을 권장합니다.
4. **Supabase 설정**: Authentication, Project URL, Public Key, Admin 역할, SQL 권한을 검증한 뒤 공개하세요. `service_role`/`sb_secret_` 키를 GitHub에 올리면 안 됩니다.
5. **백업 및 기간 관리**: Supabase 예약 데이터 백업 및 만료된 개인정보의 주기적 삭제는 운영자가 관리해야 합니다.
6. **정기 레슨 요금**: 요금을 제공받지 않아 '별도 문의'로 표기했습니다.
7. **한 시간 한 명**: 이 설계는 강사 1명 기준 **30분당 1건** 접수 모델입니다. 강사를 늘리거나 동시 레슨을 운영하려면 데이터베이스의 시간 중복 정책을 변경해야 합니다.
8. **환불 실제 처리**: 사이트와 DB가 환불금을 자동 송금하거나 추적하지 않습니다. 취소 상태 변경과 환불 실무는 별개입니다.

## 로컬 테스트(선택)

GitHub 업로드 전 컴퓨터에서 직접 확인하려면 해당 폴더에서 아래 명령으로 간단한 로컬 HTTP 서버를 열 수 있습니다.

```bash
python -m http.server 8000
```

브라우저에서 `http://localhost:8000` → 회원 페이지, `http://localhost:8000/admin.html` → 관리자 페이지.

제작에 사용한 탁구장 사진은 사용자가 직접 제공한 이미지를 크기 최적화한 것으로, AI로 새롭게 재구성한 사진이 아닙니다.
